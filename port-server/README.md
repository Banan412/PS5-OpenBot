# OpenBot port host prototype

This host prototype serves the OpenBot web build, offers local account setup, and supports a private text-only Bot conversation using an explicitly configured OpenAI-compatible model. It is incomplete: most OpenBot APIs, tools and approvals are not implemented. It is not a PS5 build and has not been verified on the console.

Build the web UI with `scripts/build-web-ps5.ps1`. From `port-server`, run `cargo run --release`. By default the server reads `../app/dist` and binds to `127.0.0.1:3010`. `OPENBOT_WWW_DIR` and `OPENBOT_BIND` configure the asset directory and listener. Set the bind address to `0.0.0.0:3010` for LAN access; visitors use the machine's current IPv4 address. At startup, a wildcard IPv4 listener prints possible network URLs discovered from local interfaces; these are a snapshot and do not prove that a firewall or network permits access. Automatic discovery on PS5 is not yet verified. Asset files are streamed from a trusted local build directory; do not allow untrusted concurrent modification of that directory.

Local authentication is disabled unless `OPENBOT_ALLOWED_ORIGIN` and `OPENBOT_DB_PATH` are set. For direct HTTP on an IPv4 listener, `OPENBOT_ALLOWED_ORIGIN=auto` checks each mutation against current local IPv4 addresses and the listener port. Alternatively specify an exact browser origin for a trusted reverse proxy. For first-owner setup, `OPENBOT_SETUP_TOKEN_FILE` names a private file containing a freshly generated high-entropy token of 32–256 characters; it expires 15 minutes after startup. Setup succeeds once. Remove the token file from configuration after setup. Database and secret directories must be private. HTTP does not encrypt passwords or session cookies; HTTPS requires a correctly configured trusted proxy, which this prototype does not provide.

To enable experimental text runs, set `OPENBOT_MODEL_URL` to a trusted OpenAI-compatible `/v1` base URL and `OPENBOT_MODEL_ID` to the model name, or `auto` to discover it at run time when the server returns exactly one model. Automatic selection fails the run if no model or multiple models are returned, and does not prevent server startup while the model is offline. No PS5 address is built into the application. The host supports one active run at a time, bounded recent history, saved text and event replay. It does not execute tools. Run-specific Phoenix replay, Phoenix stop, recorder, queues, model selection and many other features remain incomplete. The CopilotKit HTTP stop endpoint cancels the active host model request and records a stopped run. Automatic interface discovery, SQLite's ABI, and the Rust runtime on PS5 remain unverified.

A host browser check is available after building the UI and debug server: `node port-server/tests/browser-chat.cjs` from the repository root. It uses a temporary local mock model and Chrome (`CHROME_PATH` can override the default), creates a temporary account and Bot, sends a message and checks the answer after reload. It does not test PS5LM or prove complete OpenBot parity.

For a host-only Stop check, run `node port-server/tests/browser-stop.cjs`. It uses a slow local mock and verifies the browser cancels the request and retains the partial reply. Phoenix `stop_run` remains unimplemented.

To compile the current `app/dist` into the host executable, build the web UI first and run `cargo build --release --features embedded-www` from `port-server`. `OPENBOT_ASSETS_DIR` can select a different built asset directory at build time. This embeds the files as read-only bytes; the effect on PS5 executable size, resident memory, and loader compatibility has not been measured. A host browser check passed with a nonexistent `OPENBOT_WWW_DIR`, demonstrating the embedded build served its own files. This feature does not itself produce a PS5 ELF.

On Linux or WSL, `scripts/build-web.sh` performs the same pinned Bun build. Set `BUN_BIN` if Bun is not on PATH. The script requires Bun 1.4.3 and uses the repository's `ps5-brand` configuration.
